## Common contract

Every persisted operation records a stable operation ID, type, risk class,
actor, target, correlation ID, status (`PREVIEWED`, `RUNNING`, `COMPLETED`,
or `FAILED`), safe result/error code, and timestamps.
The lock applies only while an operation can conflict. A browser loss does not
erase server operation state; an Administrator can reopen the status by ID.

The fixture-recovery rehearsal uses a test-only recovery-point freshness policy
defined by the acceptance run. It is not a corporate backup retention policy.
All timeout behavior returns a controlled status and preserves operation truth;
a request timeout never fabricates a completed or failed execution.
