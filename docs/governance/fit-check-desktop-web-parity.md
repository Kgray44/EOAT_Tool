# Fit Check desktop-to-web parity matrix

The desktop implementation in `app/atlas/minimalist/fit_check.py` and
`core/fit_check_service.py` is the product reference for this work. The web
surface consumes the MySQL compatibility model, so it must render
server-authoritative evidence rather than recreate desktop engineering rules in
TypeScript.

## Intentional differences

There are no intentional desktop-only omissions in the result data. The desktop
uses an overlay for detailed evidence and a two-link linear path; the responsive
web presents that evidence directly and renders the third, already-authoritative
Machine-to-Tool relationship edge as well. This makes the complete desktop
decision model visible without changing compatibility logic or data.

## Final semantic comparison

The desktop service and web API were exercised from the same sanctioned MySQL
snapshot using the same selected Machine, Tool, and EOAT. They agreed on the
three relationship results, the seven criterion codes and ordering, and the
semantic outcome mapping: desktop `warning` is rendered as web `NEEDS_REVIEW`,
desktop `pass` as `COMPATIBLE`, and desktop `na` as `NOT_APPLICABLE`.
